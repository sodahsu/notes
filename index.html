ORCA × OPENSPEC · 給設計師與前端工程師

AI 幫你寫程式，但不要讓工作跟著變亂。

Orca 把每個功能、AI、畫面與程式修改整理在同一個工作空間。第一次來不用先背 Git 名詞；先知道「遇到什麼問題，要用哪個功能」就能開始。

白話版
開一個功能→ AI 幫你做→ 你看畫面→ 檢查改了什麼→ 收成果
工程版
integration branch→ worktree→ OpenSpec→ agent / browser→ diff / test→ commit / push
第一次用 Orca5 分鐘知道怎麼裝、怎麼開第一個功能。 我是設計師看畫面、Design Mode、Diff Review、手機 QA。 我是前端工程師Worktree、dev server、Mock、test、commit / push。 我現在就卡住了AI 沒額度、亂改、多功能衝突、忘記進度。

0 · 先回答最重要的問題

Orca 是什麼？為什麼值得用？

重點不是讓模型突然變聰明，而是讓「AI 已經進入日常開發」之後，工作還能保持清楚、可交接、可 Review。

白話：Orca

幫每個功能準備一張獨立工作桌。AI 在這張桌上做事，你可以看畫面、看修改、換 AI，最後再把成果收回來。

工程師看法：Orca

以 Git worktree 隔離功能工作目錄，並把 Agent、Terminal、Browser、Diff、Git 狀態放在同一個 workspace。

白話：OpenSpec

先寫清楚「這次要做到哪、不做到哪、哪些還不知道」，避免 AI 越做越遠。

工程師看法：OpenSpec

是功能規格與驗收邊界，不是聊天記憶。實作、Review、handoff 都可以回頭用同一份 spec 對答案。

AI 做到一半沒額度

不用重開功能，換 Agent 接手。

同時做三個功能開始打架

一個可獨立驗收的功能，一個 Worktree。

AI 說完成，但不敢信

直接看 Diff，再決定哪些變更要收。

只想調一顆按鈕

Browser / Design Mode 直接指給 AI。

比較適合：已經在用 Claude Code、Codex 等 coding agent，會碰 Git、需要同時處理多個功能、在意 Diff 與驗證的人。若只是想做完全不碰程式的 no-code 原型，Orca 不是主要解法。

1 · 第一次使用

5 分鐘先跑起來

第一次不用研究全部功能。裝好、加入 repo、開一個功能 Worktree，會看 Diff，就已經能開始。

下載 Orca

官方提供 macOS、Windows、Linux。Windows 10/11 x64、macOS Apple Silicon / Intel、Linux AppImage。

官方下載 ↗
macOS 也能用 Homebrew 
brew install --cask stablyai/orca/orca
第一次開啟

把現有 Git repo 加進 Orca，再選你已經在用的 Claude Code、Codex 等 Agent。Orca 本身不是另一個模型。

1加入你的 Git repo。 先從現有專案開始，不用為 Orca 另外建專案。
2從工作整合分支開一個功能 Worktree。 例如「會員管理」。
3先讀 / 補 OpenSpec。 先確定範圍，再讓 AI 動手。
4啟動 Agent，跑 dev server。 需要 UI 時，把 Browser 一起開起來。
5AI 做完先看 Diff。 驗證通過後再 Stage、Commit、Push。
第一天先會：Worktree一個完整功能一張工作桌。
第一天先會：在新會話中繼續AI 換班，功能不用重開。
第一天先會：DiffAI 說完成後，自己看它到底改了什麼。

做 UI 再學 Browser / Design Mode；開始多工再學 Split panes、Usage tracking。

設計師最有感的是 Browser、Design Mode、Diff Review、手機 QA。你負責判斷結果，AI 負責動程式。

4 · 我是前端工程師
每天就跑這條 SOP

        
工程師不需要另外一套教學。白話層往下一層，就是 branch、worktree、dev server、test、diff、commit。

      


      

        工作整合分支→
        Feature Worktree→
        OpenSpec→
        npm run dev→
        AI 實作→
        typecheck / test→
        Diff→
        Stage / Commit / Push→
        整合回工作整合分支
      


      

        
Worktree 怎麼切？
以「可獨立驗收的完整功能」為單位。會員管理一個、報名流程一個。UI / Mock / Interaction 通常留在同一個功能 Worktree。

        
Agent 怎麼分工？
同一功能可以換很多 AI，但功能生命週期跟著 Worktree / Git，不跟著某個聊天 session。

        
什麼叫完成？
不是 Agent 說 Done。至少要有：OpenSpec 對齊、相關 typecheck / test / build、Browser 驗證、Diff Review。

      


      

        
開新功能時，先這樣跟 AI 說

        
這個 Worktree 只處理「會員管理」。
先讀相關 OpenSpec 與現有專案結構，不要直接修改。

請先整理：
1. 需求範圍
2. 會修改的元件 / route / API layer / Mock
3. 可沿用的既有 pattern
4. 需要驗證的 typecheck / test / Browser flow
5. 目前規格中仍待確認的地方

確認範圍後再實作，不要處理其他功能。

      

    

  


  

    

      

        
5 · Orca × OpenSpec
Orca 管「工作不要亂」，OpenSpec 管「需求不要歪」

        
OpenSpec 不應只放在文件最後。它要出現在開工、AI 接手、UI 修改、Diff Review 與完成驗收。

      


      

        
開工前：定範圍
這次要做什麼、不做什麼、哪些仍待確認。Worktree 只處理這個 capability / change。

        
實作中：當共同語言
Agent 換人先讀同一份 spec。需求真的變了，更新規格；不要只改聊天記憶。

        
收工前：拿來對答案
OpenSpec 看「應該做什麼」、Browser 看「實際長什麼」、Diff 看「程式改了什麼」。三個一起對。

      


      

        
每個 Orca 功能旁邊都問一句
這一步 OpenSpec 要幫我定範圍、接手、確認 UI 行為，還是驗收？

        
未知就保持未知
SA / prototype / Mock 沒證據的業務規則，不要讓 AI 自己補成「既定規格」。標成待確認。

      

    

  


  

    

      

        
6 · 手機 / Emulator / WebView
先判斷你要測哪一種手機情境

        
這章是進階驗證。只是看 RWD，先用 Browser Device Emulation；真的要測 App / WebView / 手勢，再進 Emulator。

      


      

        
只是看手機版 RWD？
Browser Device Emulation。最快、最適合前端與設計師。

        
要測 App / WebView？
iOS / Android Emulator。測鍵盤、旋轉、手勢、權限、裝置行為。

        
人在外面看 AI？
Mobile Companion。它是遙控器，不是測試模擬器。

      


      

        A｜Browser Device Emulation：RWD 最常用
        

          同一個 localhost，只把 viewport 切成手機尺寸。適合檢查：horizontal overflow、CTA、中文字換行、表格 / Modal、sticky / fixed、touch target、spacing。
          
orca status --json
orca set device --name "iPhone 12" --worktree active --json
orca screenshot --worktree active --json
orca full-screenshot --worktree active --json

          
注意：Browser 模擬正常，不代表 iPhone Safari / Android WebView 一定正常。它主要驗 responsive CSS 與 viewport 行為。

        

      


      

        B｜iOS Simulator：真的讓 AI 點手機
        

          需要 Apple Simulator 環境的 Mac host。適合 App / WebView、鍵盤遮擋、旋轉、手勢、系統按鍵。
          
npx skills add https://github.com/stablyai/orca --skill orca-emulator --global
orca skills get orca-emulator
orca emulator list --worktree active --json
orca emulator attach "<device-name-or-udid>" --worktree active --json
orca emulator tap 0.5 0.7 --worktree active --json
orca emulator type "hello" --worktree active --json
orca emulator rotate landscape_left --worktree active --json
orca emulator button home --worktree active --json
orca emulator shutdown --worktree active --json

          
座標使用 0～1 的相對值：0,0 左上、0.5,0.5 中央、1,1 右下。

        

      


      

        C｜Android Emulator / 實機：adb skill
        

          
npx skills add https://github.com/stablyai/orca --skill orca-emulator-android --global
orca skills get orca-emulator-android

          可用於 AVD / adb-connected device 的啟動、tap、swipe、type、hardware button、安裝 / 啟動 App、permissions、accessibility tree、logcat。建議先讀 live guide，不要從記憶猜 flags。
        

      


      

        D｜OpenSpec 手機驗收要怎麼寫？
        

          不要只寫「支援 RWD」。改成可驗收條件：
          
- 390px viewport 不得出現非預期水平捲軸
- 手機版主要 CTA 必須滿寬
- CTA 不得被 fixed footer 或 virtual keyboard 遮住
- 中文標題可以換行，但不得截字
- 表格使用既定 mobile pattern，不由 AI 自行發明
- WebView 與一般 Browser 不一致時先標記待確認

        

      


      

        
手機 QA Prompt

        
先不要修改程式。

請用 iPhone 12 viewport 檢查目前頁面，依 OpenSpec 驗證：
1. horizontal overflow
2. CTA 行為
3. 中文換行 / 裁切
4. 表格 / Modal
5. sticky / fixed
6. touch target
7. spacing

先回報「問題 → 證據 → 最小修改建議」。
我確認後再實作。

      

    

  


  

    

      

        
7 · 名詞 / 指令速查
看到術語不用怕，先翻成白話

        
正式技術名稱保留，旁邊補白話。這樣設計師看得懂，工程師也不會失去精確度。

      


      

        
Worktree功能專用工作目錄。一個完整功能一張工作桌。

        
Branch這份工作的版本線。Worktree 通常會對應自己的功能 branch。

        
Agent幫你執行工作的 AI，例如 Claude Code、Codex。

        
Diff這次到底改了哪些程式。AI 說 Done 之後先看它。

        
OpenSpec功能應該做到哪裡的規格與驗收邊界。

        
Checkpoint留給自己或下一個 AI 的進度記錄：完成、未完成、下一步、限制。

      


      

        

          Browser / 手機常用
          
orca status --json
orca set device --name "iPhone 12" --worktree active --json
orca screenshot --worktree active --json

        

        

          交接時可以先叫 AI 做
          
先不要修改。
請檢查 git status、git diff、OpenSpec，
整理：已完成、未完成、問題、下一步。
不要重寫已完成部分。
